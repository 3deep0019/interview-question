# What is a Transaction?

A **transaction** is a group of database operations that are executed as a single unit of work.

Either:

```
All operations succeed
```

OR

```
All operations fail (rollback)
```

There is no partial success.

---

## Interview Answer

 A transaction ensures that a set of database operations are executed reliably as a single unit. It follows the ACID properties—Atomicity, Consistency, Isolation, and Durability—to maintain data integrity even in cases of failures, crashes, or concurrent access.

---

# Real-World Example: Bank Transfer

Suppose:

```
Account A = ₹1000
Account B = ₹500
```

Transfer ₹200 from A to B.

Steps:

```sql
UPDATE accounts
SET balance = balance - 200
WHERE id = 'A';

UPDATE accounts
SET balance = balance + 200
WHERE id = 'B';
```

---

## Without Transaction

Imagine:

```
Step 1 succeeds
Account A = ₹800

Server crashes ❌

Step 2 never runs
```

Result:

```
A = ₹800
B = ₹500
```

₹200 disappeared.

---

## With Transaction

```sql
BEGIN;

UPDATE accounts
SET balance = balance - 200
WHERE id = 'A';

UPDATE accounts
SET balance = balance + 200
WHERE id = 'B';

COMMIT;
```

If anything fails:

```sql
ROLLBACK;
```

Database returns to original state.

# ACID Properties

## A — Atomicity

### Meaning

Either everything happens or nothing happens.

```
Transfer Money
     ↓
Debit Account A
Credit Account B
```

If credit fails:

```
Rollback Debit
```

No partial updates.

---

## C — Consistency

### Meaning

Database always moves from one valid state to another valid state.

Example:

```
Total Money Before = ₹1500
Total Money After = ₹1500
```

Constraints remain valid.

Examples:

```sql
PRIMARY KEY
FOREIGN KEY
UNIQUE
CHECK
```

must always be satisfied.

---

## I — Isolation

### Meaning

Multiple transactions should not interfere with each other.

Example:

```
User A transferring money
User B checking balance
```

B should not see incomplete changes.

---

### Problem Without Isolation

```
Transaction 1:
Balance = 1000
Deduct 200
(Not committed yet)

Transaction 2:
Reads balance = 800
```

What if Transaction 1 rolls back?

Transaction 2 saw incorrect data.

This is called a:

```
Dirty Read
```

---

## D — Durability

### Meaning

Once committed, data survives crashes.

Example:

```
COMMIT
Server crashes
Restart
```

Data is still there.

Achieved using:

```
Write Ahead Logs (WAL)
Redo Logs
Disk Persistence
```

```
 │               │
YES             NO
 │               │

```

# Node.js Example (Prisma)

```js
await prisma.$transaction(async (tx) => {

  await tx.account.update({
    where: { id: 1 },
    data: {
      balance: {
        decrement: 200
      }
    }
  });

  await tx.account.update({
    where: { id: 2 },
    data: {
      balance: {
        increment: 200
      }
    }
  });

});
```

If any query fails:

```
Automatic Rollback
```

# Common Interview Questions

## Q: What happens if COMMIT is not executed?

**Answer:**

Changes remain uncommitted and are rolled back when the transaction ends or connection closes.

---

## Q: Difference Between COMMIT and ROLLBACK?

### COMMIT

```sql
COMMIT;
```

Permanently saves changes.

### ROLLBACK

```sql
ROLLBACK;
```

Undoes all changes in the transaction.

---

## Q: Why Are Transactions Important?

Because they:

- Prevent data corruption
- Maintain consistency
- Handle failures safely
- Support concurrent users

---

## Q: Can Transactions Span Multiple Tables?

Yes.

Example:

```
Orders Table
Inventory Table
Payments Table
```

All updates should succeed together.

```sql
BEGIN;

INSERT INTO orders ...
UPDATE inventory ...
INSERT INTO payments ...

COMMIT;
```

---

## Q: When Should You Avoid Long Transactions?

Long-running transactions:

- Hold locks
- Block other queries
- Increase deadlock risk
- Consume resources

Bad:

```
BEGIN
Wait 2 minutes
Update table
COMMIT
```

Good:

```
BEGIN
Execute quickly
COMMIT
```

# ACID Example to Remember

Imagine ordering a product:

```
1. Create Order
2. Deduct Inventory
3. Process Payment
4. Generate Invoice
```

If payment fails:

```
Order Removed
Inventory Restored
Invoice Removed
```

That's **Atomicity**.

Database remains valid → **Consistency**

Other users don't see half-finished order → **Isolation**

Once completed, data survives restart → **Durability**

# Senior-Level Interview Answer

A transaction is a sequence of database operations executed as a single logical unit of work. Transactions follow ACID properties: Atomicity ensures all operations succeed or fail together, Consistency guarantees the database remains valid, Isolation prevents concurrent transactions from interfering with each other, and Durability ensures committed data survives crashes. In production systems, transactions are critical for operations such as payments, order processing, inventory updates, and financial transfers where maintaining data integrity is essential.
