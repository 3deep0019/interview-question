**CORS (Cross-Origin Resource Sharing)** is a browser security mechanism that controls whether a web page can make requests to a different origin (domain, protocol, or port).

---

## Interview Answer

```
CORS is a browser security feature that restricts 
web applications from making requests to a different 
origin unless the server explicitly allows it using CORS headers.
```

---

## What is an Origin?

An origin consists of:

```
Protocol + Domain + Port
```

Example:

|URL|Origin|
|---|---|
|https://app.com|https://app.com|
|https://api.app.com|Different Origin|
|http://app.com|Different Origin|
|https://app.com:3000|Different Origin|

---

## Same-Origin Request (Allowed)

Frontend:

```
https://app.com
```

API:

```
https://app.com/api/users
```

Browser allows it.

---

## Cross-Origin Request (Blocked)

Frontend:

```
http://localhost:3000
```

Backend:

```
http://localhost:5000
```

JavaScript:

```
fetch('http://localhost:5000/users');
```

Browser Error:

```
Access to fetch at 'http://localhost:5000'
has been blocked by CORS policy
```

---

# Why Does CORS Exist?

Imagine you're logged into your bank:

```
bank.com
```

A malicious website:

```
hacker.com
```

tries:

```
fetch('https://bank.com/transfer-money');
```

Without CORS:

```
Money transferred 😱
```

CORS prevents unauthorized websites from reading responses from another origin.

---

# How CORS Works

### Browser sends request

```
GET /users
Origin: http://localhost:3000
```

### Server responds

```
Access-Control-Allow-Origin: http://localhost:3000
```

Browser checks:

```
Origin matches?
     ↓
   YES
     ↓
Allow Response
```

# Node.js Example

Install:

```bash
npm install cors
```

Use:

```js
const express = require('express');
const cors = require('cors');

const app = express();

app.use(cors());

app.listen(5000);
```

This allows all origins.

# Restrict Specific Origins

```js
app.use(cors({
  origin: 'http://localhost:3000'
}));
```

Response Header:

```
Access-Control-Allow-Origin: http://localhost:3000
```

---

# Multiple Allowed Origins

```js
const allowedOrigins = [
  'https://myapp.com',
  'https://admin.myapp.com'
];

app.use(cors({
  origin: function(origin, callback) {

    if (
      !origin ||
      allowedOrigins.includes(origin)
    ) {
      callback(null, true);
    } else {
      callback(new Error('Not Allowed'));
    }

  }
}));
```

# Preflight Request (OPTIONS)

For requests like:

```js
fetch('/users', {
  method: 'PUT',
  headers: {
    Authorization: 'Bearer token'
  }
});
```

Browser first sends:

```http
OPTIONS /users
```

Called a **Preflight Request**.

Purpose:

```
"Server, are you okay with this request?"
```

---

### Browser Sends

```http
OPTIONS /users

Origin: http://localhost:3000
Access-Control-Request-Method: PUT
Access-Control-Request-Headers: Authorization
```

---

### Server Responds

```http
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET,POST,PUT
Access-Control-Allow-Headers: Authorization
```

Then browser sends actual PUT request.

---

# Important CORS Headers

### Allow Origin

```http
Access-Control-Allow-Origin: *
```

or

```http
Access-Control-Allow-Origin: https://myapp.com
```

---

### Allow Methods

```http
Access-Control-Allow-Methods:GET, POST, PUT, DELETE
```

---

### Allow Headers

```http
Access-Control-Allow-Headers:Authorization, Content-Type
```

---

### Allow Credentials

```http
Access-Control-Allow-Credentials: true
```

Required for:

- Cookies
- Sessions
- Auth credentials

---

# Credentials Example

Frontend:

```js
fetch('/api/users', {
  credentials: 'include'
});
```

Backend:

```js
app.use(cors({
  origin: 'http://localhost:3000',
  credentials: true
}));
```

Response:

```http
Access-Control-Allow-Credentials: true
```

```js
app.use(cors({

    'https://admin.company.com'
  ],
  credentials: true,
  methods: [
    'GET',

    'PUT',
    'DELETE'
```

# Common Interview Questions

### Q: Is CORS a frontend or backend concept?

**Answer:**

Both.

- Browser enforces CORS.
- Server provides CORS headers.

---

### Q: Does Postman have CORS issues?

**Answer:**

No.

Postman is not a browser.

```
Browser → CORS enforced
Postman → No CORS
```

---

### Q: What is a Preflight Request?

**Answer:**

An `OPTIONS` request automatically sent by the browser before certain cross-origin requests to verify permissions.

---

### Q: Why does `Access-Control-Allow-Origin: *` not work with cookies?

**Answer:**

When credentials are used:

```http
Access-Control-Allow-Credentials: true
```

you must specify an exact origin.

```http
Access-Control-Allow-Origin: https://app.com
```

`*` is not allowed.

---

### Q: Can CORS stop someone from calling my API?

**Answer:**

No.

CORS only restricts browsers.

```
Browser ❌ Blocked
Postman ✅ Works
Curl ✅ Works
Backend Service ✅ Works
```

Authentication and authorization are still required.

# Senior-Level Interview Answer

```
CORS (Cross-Origin Resource Sharing) is a browser security mechanism that allows a server to specify which origins can access its resources. 
When a browser makes a cross-origin request, 
it checks the server's CORS headers such as 
`Access-Control-Allow-Origin`, 
`Access-Control-Allow-Methods`, and 
`Access-Control-Allow-Headers`. 
For complex requests, browsers first send a preflight `OPTIONS` request to verify permissions. 
CORS is enforced by browsers only and is not a replacement for authentication or authorization. It primarily protects users from unauthorized cross-site interactions.
```
