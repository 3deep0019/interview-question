`next()` is a function provided by **Express** that passes control from the current middleware to the next middleware in the request-response cycle.

Think of Express as a chain:

```
Request
   ↓
Middleware 1
   ↓ next()
Middleware 2
   ↓ next()
Middleware 3
   ↓ next()
Route Handler
   ↓
Response
```

If you don't call `next()` and don't send a response, the request will hang forever.

---

# How Express Processes a Request

Example:

```js
const express = require("express");
const app = express();

app.use((req, res, next) => {
  console.log("Middleware 1");
  next();
});

app.use((req, res, next) => {
  console.log("Middleware 2");
  next();
});

app.get("/", (req, res) => {
  console.log("Route Handler");
  res.send("Hello");
});

app.listen(3000);
```

Request:

```
GET /
```

Output:

```
Middleware 1
Middleware 2
Route Handler
```

Flow:

```
Request
   ↓
Middleware 1
   ↓ next()
Middleware 2
   ↓ next()
Route Handler
   ↓
Response
```

# What Happens If You Don't Call `next()`?

```js
app.use((req, res, next) => {
  console.log("Middleware 1");
});
```

Request:

```
GET /
```

Output:

```
Middleware 1
```

Browser:

```
Loading...Loading...Loading...
```

Why?

Because Express is waiting for:

```js
next()
```

or

```js
res.send()
```

Neither happened.

# `next()` vs `res.send()`

## Option 1: Continue

```js
app.use((req, res, next) => {
  console.log("Checking Auth");
  next();
});
```

Moves forward.

---

## Option 2: End Request

```js
app.use((req, res, next) => {
  res.status(401).send("Unauthorized");
});
```

Stops here.

Flow:

```
Request
   ↓
Middleware
   ↓
Response Sent
   ↓
END
```

No `next()` needed.

# Real Example: Authentication Middleware

```js
function auth(req, res, next) {
  const token = req.headers.authorization;

  if (!token) {
    return res.status(401).send("No Token");
  }

  next();
}

app.get("/profile", auth, (req, res) => {
  res.send("Profile Data");
});
```

Request without token:

```
Request
   ↓
Auth Middleware
   ↓
401 Response
```

Request with token:

```
Request
   ↓
Auth Middleware
   ↓ next()
Route Handler
   ↓
Response
```

# `next(err)` - Error Handling

This is one of the most important uses.

```js
app.get("/users", (req, res, next) => {
  const error = new Error("Database Failed");

  next(error);
});
```

Express immediately skips normal middleware:

```
Request
   ↓
Route
   ↓
next(err)
   ↓
Error Middleware
```

---

# Error Middleware

```js
app.use((err, req, res, next) => {
  console.log(err.message);

  res.status(500).json({
    message: err.message,
  });
});
```

Output:

```json
{
  "message": "Database Failed"
}
```

---

# Why Error Middleware Has 4 Parameters

Normal middleware:

```js
(req, res, next)
```

Error middleware:

```js
(err, req, res, next)
```

Express identifies error handlers by checking:

```js
function.length
```

Example:

```js
(req, res, next)       // 3 args
(err, req, res, next)  // 4 args
```

When Express sees 4 parameters:

```js
(err, req, res, next)
```

it registers it as an error handler.

# Async Example

```js
app.get("/users", async (req, res, next) => {
  try {
    const users = await prisma.user.findMany();

    res.send(users);
  } catch (err) {
    next(err);
  }
});
```

Flow:

```
Prisma Error
     ↓
catch
     ↓
next(err)
     ↓
Error Middleware
```

This is the standard Express 4 pattern.

# Middleware Order Matters

```js
app.use(auth);

app.get("/", controller);
```

Flow:

```
Request
   ↓
auth
   ↓
controller
```

If reversed:

```
app.get("/", controller);

app.use(auth);
```

Flow:

```
Request
   ↓
controller
```

Auth never runs.

### Logger

```js
app.use((req, res, next) => {

```

---

### Request Timing

```js
app.use((req, res, next) => {
  req.startTime = Date.now();

  next();
});
```

---

### Role Validation

```js
app.use((req, res, next) => {
  if (req.user.role !== "admin") {
    return res.status(403).send("Forbidden");
  }

  next();
});
```

# Senior Interview Answer

`next()` is a callback provided by Express that transfers control to the next middleware in the request-processing pipeline. It enables middleware chaining and separation of concerns such as authentication, logging, validation, and error handling. Calling `next()` continues normal execution, while `next(err)` bypasses normal middleware and invokes the nearest error-handling middleware. Express internally maintains a middleware stack, and `next()` advances the request through that stack.
