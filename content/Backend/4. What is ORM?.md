**ORM (Object Relational Mapping)** is a technique that allows developers to interact with a relational database using programming language objects instead of writing raw SQL queries.

In Node.js, popular ORMs are:
- Prisma
- Sequelize
- TypeORM
- MikroORM

---

# Without ORM

SQL Query:

```sql
SELECT * FROM users WHERE id = 1;
```

Node.js:

```js
const result = await pool.query(
  'SELECT * FROM users WHERE id = $1',
  [1]
);
```

---

# With ORM (Prisma)

```js
const user = await prisma.user.findUnique({
  where: {
    id: 1
  }
});
```

ORM converts this into SQL internally.

```
Prisma Query
      ↓
Generated SQL
      ↓
Database
      ↓
Result Object
```

---

# Why Use ORM?

### 1. Better Developer Productivity

Instead of:

```sql
SELECT name,email
FROM users
WHERE id=1;
```

You write:

```js
await prisma.user.findUnique({
  where: { id: 1 }
});
```

---

### 2. Type Safety

Prisma example:

```js
await prisma.user.findUnique({
  where: {
    email: 'test@test.com'
  }
});
```

Auto-completion and compile-time validation.

---

### 3. Database Abstraction

Same code can work with:

- PostgreSQL
- MySQL
- SQL Server

Minimal code changes.

---

### 4. Relationship Handling

Tables:

```
Users
Orders
```

SQL:

```sql
SELECT *
FROM users u
JOIN orders o
ON u.id = o.user_id;
```

Prisma:

```js
const user = await prisma.user.findUnique({
  where: { id: 1 },
  include: {
    orders: true
  }
});
```

# Prisma Example

Schema:

```prisma
model User {
  id    Int    @id @default(autoincrement())
  name  String
  email String @unique
}
```

Create:

```js
await prisma.user.create({
  data: {
    name: 'John',
    email: 'john@test.com'
  }
});
```

Read:

```js
await prisma.user.findMany();
```

Update:

```js
await prisma.user.update({
  where: { id: 1 },
  data: { name: 'Jane' }
});
```

Delete:

```js
await prisma.user.delete({
  where: { id: 1 }
});
```

# ORM vs Raw SQL

|ORM|Raw SQL|
|---|---|
|Easier to write|More control|
|Faster development|Better optimization|
|Type safety|No abstraction|
|Database agnostic|Database specific|
|Learning curve lower|Requires SQL expertise|

# When ORM Can Be Slow

Example:

```js
const users = await prisma.user.findMany({
  include: {
    orders: true,
    payments: true,
    addresses: true
  }
});
```

May generate multiple joins and return excessive data.

Sometimes raw SQL performs better.

```js
await prisma.$queryRaw`
SELECT ...
`;
```

---

# N+1 Query Problem

Bad:

```js
const users = await prisma.user.findMany();

for (const user of users) {
  await prisma.order.findMany({
    where: {
      userId: user.id
    }
  });
}
```

If:

```
100 Users
```

Queries executed:

```
1 query for users
100 queries for orders
```

Total:

```
101 Queries
```

This is called the **N+1 Problem**.

Better:

```js
await prisma.user.findMany({
  include: {
    orders: true
  }
});
```

# Migrations

ORMs manage database schema changes.

Example:

```bash
npx prisma migrate dev
```

Creates:

```sql
ALTER TABLE users
ADD COLUMN phone VARCHAR(255);
```

Automatically.

# Common Interview Questions

### Q: What is ORM?

**Answer:**

ORM is a technique that maps database tables to programming language objects, allowing developers to perform database operations without writing raw SQL.

---

### Q: What are the advantages of ORM?

- Faster development
- Readable code
- Type safety
- Relationship management
- Migration support
- Database abstraction

---

### Q: What are the disadvantages?

- Performance overhead
- Complex queries can be difficult
- Hidden SQL generation
- Risk of N+1 query issues

---

### Q: When would you use raw SQL instead of ORM?

- Complex joins
- Analytics queries
- Large reporting queries
- Performance-critical operations
- Bulk data processing

Example:

```js
await prisma.$queryRaw`
SELECT COUNT(*)
FROM orders
GROUP BY status;
`;
```

---

### Q: Does ORM replace SQL knowledge?

**Answer:**

No. A good developer still needs strong SQL knowledge because ORMs generate SQL under the hood, and debugging or optimizing queries often requires understanding SQL.

---

# Senior-Level Interview Answer

ORM (Object Relational Mapping) is a technique that maps relational database tables to objects in application code. It simplifies CRUD operations, relationship management, schema migrations, and improves developer productivity. In Node.js, tools like Prisma and Sequelize are commonly used. While ORMs accelerate development and provide type safety, they can introduce performance overhead and issues like N+1 queries. For complex or performance-sensitive workloads, I often combine ORM usage with optimized raw SQL queries where necessary.
