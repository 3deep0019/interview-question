**`next(error)`** — skip all remaining normal middleware and jump straight to the error-handling middleware, which has a **four-argument** signature `(err, req, res, next)`:

```js
// Any middleware / route
app.get('/user/:id', async (req, res, next) => {
  try {
    const user = await db.getUser(req.params.id);
    if (!user) return next({ status: 404, message: 'not found', expose: true });
    res.json(user);
  } catch (err) {
    next(err); // jumps to the error handler
  }
});

// Error handler — MUST have 4 args, Express detects by arity
app.use((err, req, res, next) => {
  req.log.error({ err }, 'unhandled');
  res.status(err.status || 500).json({
    error: err.expose ? err.message : 'Internal Server Error',
  });
});
```

Points to hit:

- **Order matters** — middleware runs top-down. Body parser before handlers that read `req.body`. Auth before protected routes. Error middleware **last**.
- **Async errors** (pre-Express 5) don't reach `next` automatically — wrap with a `try/catch` or an async-wrapper. Express 5 handles this natively.
- **Arity is how Express distinguishes** normal (3-arg) from error (4-arg) middleware.
