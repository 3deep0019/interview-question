Pagination is the process of **splitting large datasets into smaller chunks (pages)** instead of returning all records at once.

Without pagination:

```
1,000,000 Records
       ↓
Single API Response
       ↓
Slow API
High Memory Usage
Network Overhead
Poor User Experience
```

With pagination:

```
Page 1 → 20 Records
Page 2 → 20 Records
Page 3 → 20 Records
```

---

# Interview Answer

```
Pagination is a technique used to limit the amount of data returned by a query or API response. It improves performance, reduces memory usage, decreases network payload size, and provides a better user experience when dealing with large datasets.
```

---

# Offset Pagination

The most common approach.

## SQL

```sql
SELECT *
FROM users
ORDER BY id
LIMIT 10 OFFSET 20;
```

Meaning:

```
Skip first 20 rows
Return next 10 rows
```

---

## API Example

Request:

```http
GET /users?page=3&limit=10
```

Backend:

```js
const page = 3;
const limit = 10;

const offset = (page - 1) * limit;
```

Calculation:

```
(3 - 1) * 10
=
20
```

SQL:

```sql
LIMIT 10 OFFSET 20
```

---

## Prisma Example

```js
const users = await prisma.user.findMany({
  skip: 20,
  take: 10
});
```

---

## Result

```
Page 1 → Records 1-10
Page 2 → Records 11-20
Page 3 → Records 21-30
```

---

# Problems with Offset Pagination

Imagine:

```
100 Million Records
```

Query:

```sql
SELECT *
FROM users
LIMIT 10 OFFSET 50000000;
```

Database must:

```
Read 50,000,000 rows
Discard them
Return 10 rows
```

Very expensive.

---

## Another Problem: Data Changes

Current Data:

```
1
2
3
4
5
```

User loads:

```
Page 1
```

Before Page 2:

```
New record inserted
```

Now:

```
0
1
2
3
4
5
```

Page 2 may contain duplicates or missing records.

# Cursor Pagination (Preferred)

Instead of page numbers:

```
Give me records after ID 100
```

---

## SQL

```sql
SELECT *
FROM users
WHERE id > 100
ORDER BY id
LIMIT 10;
```

---

## Prisma

```js
const users = await prisma.user.findMany({
  take: 10,
  cursor: {
    id: 100
  },
  skip: 1
});
```

---

## Result

```
Last Record = 100

Next Query:
id > 100

Returns:
101
102
103
...
```

# Offset vs Cursor Pagination

|Feature|Offset|Cursor|
|---|---|---|
|Easy implementation|✅|❌|
|Page numbers|✅|❌|
|Performance on large tables|❌|✅|
|Consistent results|❌|✅|
|Infinite scrolling|❌|✅|
|Large datasets|❌|✅|

# Important Index Requirement

Cursor pagination requires indexed columns.

Good:

```sql
id
created_at
```

Index:

```sql
CREATE INDEX idx_users_created_at
ON users(created_at);
```

Without indexes:

```
Full Table Scan
Slow Query
```

# Common Interview Questions

### Q: Why is OFFSET slow?

**Answer:**

Because the database must scan and discard all rows before the offset position.

Example:

```sql
OFFSET 1000000
```

Database reads one million rows before returning data.

---

### Q: Which pagination is best for large datasets?

**Answer:**

Cursor pagination because it uses indexed lookups rather than scanning and skipping rows.

---

### Q: Which pagination does Instagram or LinkedIn use?

**Answer:**

Cursor-based pagination because feeds contain millions of records and require infinite scrolling with consistent ordering.

---

### Q: Can OFFSET cause duplicate records?

**Answer:**

Yes. If records are inserted or deleted between requests, users may see duplicates or miss records.

---

# Senior-Level Interview Answer


Pagination is used to limit the amount of data returned from a database query. The simplest approach is offset-based pagination using `LIMIT` and `OFFSET`, which works well for small datasets and page-based navigation. However, offset pagination becomes inefficient at scale because the database must scan and discard rows before reaching the requested offset. For large datasets and infinite-scroll use cases, I prefer cursor-based pagination using an indexed column such as `id` or `created_at`, as it provides better performance, consistency, and scalability. In production systems, offset pagination is common for admin dashboards, while cursor pagination is typically used for high-volume feeds and APIs.
