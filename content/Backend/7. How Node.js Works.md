#### 1. Built on Google's V8 Engine

Node.js uses the **V8 JavaScript engine** (the same engine used in the Chrome browser) to execute JavaScript code.

```js
console.log("Hello, Node.js!");
```

V8 compiles JavaScript into machine code, making execution very fast.

---

#### 2. Single-Threaded Event Loop

Unlike many traditional servers that create a new thread for each request, Node.js uses:

- **One main thread**
- **An Event Loop**
- **Non-blocking I/O**

This allows Node.js to handle thousands of connections efficiently.

### Traditional Server

```
Request 1 → Thread 1
Request 2 → Thread 2
Request 3 → Thread 3
```

### Node.js

```
Requests
    ↓
Event Queue
    ↓
Event Loop
    ↓
Single Thread
```

---

#### 3. Non-Blocking I/O

When Node.js performs a slow operation (reading a file, database query, API call), it does **not wait** for it to finish.

Example:

```js
const fs = require('fs');

console.log("Start");

fs.readFile('data.txt', 'utf8', (err, data) => {
    console.log(data);
});

console.log("End");
```

**Output:**

```
Start
End
(file contents)
```

Why?

- `readFile()` starts the file operation.
- Node.js continues executing other code.
- When the file is ready, the callback is placed in the queue.
- The Event Loop executes the callback.

---

#### 4. Event Loop

The Event Loop continuously checks:

1. Is the call stack empty?
2. Are there tasks waiting in the queue?

If yes, it moves tasks from the queue to the call stack.

```
┌─────────────┐
│ Call Stack  │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Event Loop  │
└──────┬──────┘
       │
       ▼
┌─────────────┐
│ Callback    │
│ Queue       │
└─────────────┘
```

---

#### 5. Behind the Scenes: libuv

Node.js uses a library called **libuv** that provides:

- Event loop
- Thread pool
- Async file operations
- Networking

For operations like:

- File system access
- DNS lookups
- Compression
- Cryptography

libuv uses a small thread pool in the background, while your JavaScript code remains single-threaded.

---

#### Example Request Flow

When a user requests a webpage:

```
Client Request
      ↓
Node.js Server
      ↓
Database Query (async)
      ↓
Node continues handling other requests
      ↓
Database returns result
      ↓
Callback executed
      ↓
Response sent to client
```

## Understanding **Microtasks vs Macrotasks** is the key to mastering the Event Loop.

Think of JavaScript as having **three queues**:

```
Call Stack
    ↓
nextTick Queue (Node.js only)
    ↓
Microtask Queue
    ↓
Macrotask Queue (Event Loop Phases)
```

---

# What is a Task?

A task is simply a piece of code waiting to execute.

JavaScript divides tasks into:

1. **Microtasks** (higher priority)
2. **Macrotasks** (lower priority)

---

# Microtasks

Microtasks execute **immediately after the current synchronous code finishes** and **before the Event Loop moves to the next phase**.

Examples:

```
Promise.then()
Promise.catch()
Promise.finally()
queueMicrotask()
```

Example:

```
console.log("A");

Promise.resolve().then(() => {
  console.log("B");
});

console.log("C");
```

Execution:

```
Call Stack:
A
Promise registered
C

Call Stack Empty
↓
Run Microtasks
↓
B
```

Output:

```
A
C
B
```

---

# queueMicrotask()

Same queue as Promise.

```js
console.log("Start");

queueMicrotask(() => {
  console.log("Microtask");
});

console.log("End");
```

Output:

```
Start
End
Microtask
```

---

# Macrotasks

Macrotasks are executed by the Event Loop phases.

Examples:

```js
setTimeout()
setInterval()
setImmediate()
I/O Callbacks
HTTP Requests
File Reads
```

Example:

```js
console.log("A");

setTimeout(() => {
  console.log("B");
}, 0);

console.log("C");
```

Output:

```
A
C
B
```

Why?

Because timer callbacks wait until the Event Loop reaches the Timer phase.

---

# Microtask vs Macrotask

```js
console.log("1");

setTimeout(() => {
  console.log("2");
}, 0);

Promise.resolve().then(() => {
  console.log("3");
});

console.log("4");
```

Execution:

### Synchronous code

```
1
4
```

### Microtask Queue

```
3
```

### Macrotask Queue

```
2
```

Output:

```
1
4
3
2
```

Microtask wins.

---

# In Node.js: process.nextTick is Even Higher

Node adds a special queue:

```js
process.nextTick()
```

Priority:

```
Current Code
↓
process.nextTick
↓
Microtasks
↓
Macrotasks
```

Example:

```js
console.log("1");

process.nextTick(() => {
  console.log("2");
});

Promise.resolve().then(() => {
  console.log("3");
});

setTimeout(() => {
  console.log("4");
}, 0);

console.log("5");
```

Output:

```
1
5
2
3
4
```

# Code

```js
const fs = require("fs");

console.log("Start");

process.nextTick(() => {
  console.log("nextTick");
});

Promise.resolve().then(() => {
  console.log("Promise");
});

queueMicrotask(() => {
  console.log("Microtask");
});

setTimeout(() => {
  console.log("Timer");
}, 0);

setImmediate(() => {
  console.log("Immediate");
});

fs.readFile(__filename, () => {
  console.log("Poll");
});

console.log("End");
```

---

# Step 1: Execute Synchronous Code

JavaScript starts executing line by line on the Call Stack.

```js
console.log("Start");
```

Output:

```
Start
```

---

## Register nextTick

```js
process.nextTick(() => {
  console.log("nextTick");
});
```

Callback goes into the **Next Tick Queue**.

Nothing executes yet.

---

## Register Promise

```js
Promise.resolve().then(() => {
  console.log("Promise");
});
```

Callback goes into the **Microtask Queue**.

Nothing executes yet.

---

## Register queueMicrotask

```js
queueMicrotask(() => {
  console.log("Microtask");
});
```

Also goes into the **Microtask Queue**.

Current queues:

```
NextTick Queue
└── nextTick

Microtask Queue
├── Promise
└── Microtask
```

---

## Register Timer

```js
setTimeout(() => {
  console.log("Timer");
}, 0);
```

Callback is registered for the **Timers Phase**.

---

## Register Immediate

```js
setImmediate(() => {
  console.log("Immediate");
});
```

Callback is registered for the **Check Phase**.

---

## Register File Read

```js
fs.readFile(__filename, () => {
  console.log("Poll");
});
```

Node delegates file reading to **libuv Thread Pool**.

The callback will execute later in the **Poll Phase** once the file read completes.

---

## Last Synchronous Statement

```js
console.log("End");
```

Output:

```
Start
End
```

At this point the Call Stack is empty.

---

# Current State

```
Call Stack
(empty)

NextTick Queue
└── nextTick

Microtask Queue
├── Promise
└── Microtask

Event Loop Queues
├── Timer
├── Immediate
└── File Read
```

---

# Step 2: Drain process.nextTick Queue

Node always executes the Next Tick Queue before anything else.

```js
console.log("nextTick");
```

Output:

```
Start
End
nextTick
```

Queue becomes empty.

---

# Step 3: Drain Microtask Queue

Node now executes all microtasks in FIFO order.

First:

```js
console.log("Promise");
```

Output:

```
Start
End
nextTick
Promise
```

Second:

```js
console.log("Microtask");
```

Output:

```
Start
End
nextTick
Promise
Microtask
```

Microtask Queue is now empty.

---

# Step 4: Enter Event Loop

Now Node starts processing Event Loop phases.

---

# Timers Phase

Node checks:

```js
setTimeout(..., 0);
```

Timer is ready.

Executes:

```
console.log("Timer");
```

Output:

```
Start
End
nextTick
Promise
Microtask
Timer
```

---

# Pending Callbacks Phase

Used for some internal system callbacks.

Your code has nothing here.

```
(No output)
```

---

# Idle / Prepare Phase

Internal libuv work.

Not accessible from user code.

```
(No output)
```

---

# Poll Phase

Node checks for completed I/O operations.

Your file read may or may not have completed yet.

```js
fs.readFile(__filename)
```

If the file read has completed:

```js
console.log("Poll");
```

runs.

If not, Node moves on.

This is why Poll and Immediate can switch order.

---

# Check Phase

Node executes:

```js
setImmediate(...)
```

Output:

```
Immediate
```

---

# Possible Outputs

### Output 1

```
Start
End
nextTick
Promise
Microtask
Timer
Poll
Immediate
```

### Output 2

```
Start
End
nextTick
Promise
Microtask
Timer
Immediate
Poll
```

Both are valid.

---

# Why Poll and Immediate Can Swap

The file read is executed by libuv's thread pool.

```js
fs.readFile(__filename)
```

does not complete instantly.

Node reaches the Poll phase and asks:

```
Has file reading finished?
```

### Case 1

```
Yes
```

Execute Poll callback first.

```
PollImmediate
```

---

### Case 2

```
No
```

Move to Check phase.

```
Immediate
```

Later, when file reading finishes:

```
Poll
```

# Final Interview Notes

```
1. Synchronous code runs first.

2. process.nextTick() has the highest priority in Node.js.

3. Promise.then() and queueMicrotask() are microtasks.

4. All microtasks run before the Event Loop continues.

5. setTimeout() executes in the Timers phase.

6. fs.readFile() callback executes in the Poll phase.

7. setImmediate() executes in the Check phase.

8. Poll and setImmediate ordering is not guaranteed unless you're already inside an I/O callback.

9. Typical output:

Start
End
nextTick
Promise
Microtask
Timer
Immediate/Poll
Poll/Immediate
```
