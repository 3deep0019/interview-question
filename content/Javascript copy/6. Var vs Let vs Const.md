# 1. Scope

## var → Function Scoped

```js
function demo() {
    if (true) {
        var a = 10;
    }

    console.log(a);
}

demo();
```

Output:

```
10
```

Why?

`var` ignores block boundaries.

JavaScript sees:

```js
function demo() {
    var a;

    if (true) {
        a = 10;
    }

    console.log(a);
}
```

---

## let → Block Scoped

```js
if (true) {
    let a = 10;
}

console.log(a);
```

Output:

```
ReferenceError
```

Because:

```js
{
   let a = 10;
}
```

`a` only exists inside the block.

---

## const → Block Scoped

```js
if (true) {
    const a = 10;
}

console.log(a);
```

Output:

```
ReferenceError
```

Same reason.

# 2. Hoisting

## var

```js

```

Output:

```

```

JavaScript internally:

```js
var a;

a = 10;
```

## let

```js

```


Because `a` is in TDZ.

## const


Also TDZ.

# Important Interview Trap

## const Object

Many developers think:

```js
const = immutable
```

Wrong.

```js
const user = {
    name: "John"
};

user.name = "Bob";

console.log(user.name);
```

Output:

```
Bob
```

Works.

Why?

Because:

```
Reference is constantObject is mutable
```

---

### This Fails

```js
const user = {
    name: "John"
};

user = {};
```

Output:

```
TypeError
```

Because the reference changes.

# Closures + var vs let

## var

```js
for (var i = 0; i < 3; i++) {
    setTimeout(() => {
        console.log(i);
    }, 0);
}
```

Output:

```
333
```

One shared variable.

---

## let

```js
for (let i = 0; i < 3; i++) {
    setTimeout(() => {
        console.log(i);
    }, 0);
}
```

Output:

```
0
1
2
```

New binding per iteration.

# Which One Should You Use?

### Use const by default

```js
const API_URL = "...";
```

Most variables don't change.

---

### Use let when value changes

```js
let count = 0;

count++;
```

---

### Avoid var

Modern JavaScript rarely uses it.

Problems:

- Function scope
- Redeclaration
- Hoisting confusion

---

# Senior Interview Answer (1 Minute)

`var` is function-scoped, hoisted, can be redeclared, and is initialized with `undefined`. 
`let` and `const` are block-scoped, hoisted but remain in the Temporal Dead Zone until initialized. 
`let` allows reassignment while `const` does not. 
`const` does not make objects immutable; it only prevents reassignment of the reference. In modern JavaScript, 
I use `const` by default, `let` when reassignment is required, and generally avoid `var` because it can lead to scope and hoisting-related bugs.
