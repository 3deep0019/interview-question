**"A closure keeps a reference to the variable, not a copy of its value."**

This is the most important thing to understand about closures.

### Example 1: Reference, Not Value

```js
function outer() {
    let count = 0;

    return function() {
        console.log(count);
    };
}

const fn = outer();
```

When `fn` is created, JavaScript does **not** do this:

```js
fn = function() {
    console.log(0);
}
```

Instead, it remembers:

```
fn
 ↓
count variable
```

The function holds a reference (pointer) to the actual variable.

---

### Proof

```js
function outer() {
    let count = 0;

    return {
        increment() {
            count++;
        },

        print() {
            console.log(count);
        }
    };
}

const obj = outer();

obj.print();
obj.increment();
obj.print();
obj.increment();
obj.print();
```

Output:

```
0
1
2
```

If closures stored a copy of the value, `print()` would always show `0`.

Instead, it sees the latest value because it's referencing the same variable.

### Your `for` Loop Example

```js
let i;

for (i = 0; i < 3; i++) {
    arrfn.push(function() {
        console.log(i);
    });
}
```

Each function remembers:

```
same
```

Because each iteration gets its own binding. explain

This is the key concept behind why `let` behaves differently from `var` in a loop.

## With `var` (or one shared variable)

```js
let i;

for (i = 0; i < 3; i++) {
    arrfn.push(() => {
        console.log(i);
    });
}
```

There is only **one variable `i`**.

Memory:

```
i = 0
     ↑
    fn1

i = 1
     ↑
    fn2

i = 2
     ↑
    fn3
```

Actually all functions point to the same `i`.

After loop ends:

```
i = 3

fn1 ──┐
fn2 ──┼──► i = 3
fn3 ──┘
```

Output:

```
3
3
3
```

---

# With `let`

```js
for (let i = 0; i < 3; i++) {
    arrfn.push(() => {
        console.log(i);
    });
}
```

Most people say:

> "let is block scoped."

That's true, but the real magic is:

> **JavaScript creates a new `i` for every iteration of the loop.**

---

### Iteration 1

```js
let i = 0;
```

Function created:

```js
() => console.log(i)
```

Closure remembers:

```
fn1 ──► i = 0
```

---

### Iteration 2

JavaScript creates a completely new variable:

```js
let i = 1;
```

Function created:

```
fn2 ──► i = 1
```

---

### Iteration 3

Again a new variable:

```js
let i = 2;
```

Function created:

```js
fn3 ──► i = 2
```

Memory looks like:

```
fn1 ──► i(0)

fn2 ──► i(1)

fn3 ──► i(2)
```

Notice:

```
Different variables
```

not

```
Same variable
```

---

## Think of JavaScript doing this internally

Your code:

```js
for (let i = 0; i < 3; i++) {
    arrfn.push(() => console.log(i));
}
```

Conceptually becomes:

```js
{
    let i0 = 0;
    arrfn.push(() => console.log(i0));
}

{
    let i1 = 1;
    arrfn.push(() => console.log(i1));
}

{
    let i2 = 2;
    arrfn.push(() => console.log(i2));
}
```

Now it's obvious:

```
fn1 -> i0 -> 0
fn2 -> i1 -> 1
fn3 -> i2 -> 2
```

Output:

```
0
1
2
```

---

## Interview Answer

If asked:

Why does `let` print `0 1 2`?

Answer:

In a `for` loop, `let` creates a new lexical binding for each iteration. Each closure captures a different binding of `i`, so the first function captures `i=0`, the second captures `i=1`, and the third captures `i=2`. With `var` or a shared variable, all closures capture the same variable, which ends up as `3` after the loop completes.
