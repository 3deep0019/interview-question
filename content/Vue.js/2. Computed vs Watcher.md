## Computed

Used when you want to **derive a value from existing state**.

```js
const firstName = ref('Trideep');
const lastName = ref('Ghosh');

const fullName = computed(() => {
  return `${firstName.value} ${lastName.value}`;
});
```

Template:

```
{{ fullName }}
```

Output:

```
Trideep Ghosh
```

### Characteristics

✅ Returns a value  
✅ Cached  
✅ Synchronous  
✅ Best for derived state

---

## Watch

Used when you want to **perform a side effect** when data changes.

```js
const search = ref('');

watch(search, async (newValue) => {
  await fetchUsers(newValue);
});
```

When user types:

```
t
tr
tri
trid
```

The watcher triggers and performs an API call.

### Characteristics

✅ Executes code when data changes  
✅ Supports async operations  
✅ Not cached  
✅ Best for side effects

---

# Example 1: Full Name

### Wrong (Watcher)

```js
const firstName = ref('John');
const lastName = ref('Doe');
const fullName = ref('');

watch([firstName, lastName], () => {
  fullName.value =
    `${firstName.value} ${lastName.value}`;
});
```

Problems:

- Extra state
- More code
- Easy to create bugs

---

### Correct (Computed)

```js
const fullName = computed(() => {
  return `${firstName.value} ${lastName.value}`;
});
```

Interview answer:

> If I'm deriving a value from existing reactive state, I use computed rather than a watcher.

---

# Example 2: Search API

### Wrong (Computed)

```js
const users = computed(async () => {
  return await fetchUsers(search.value);
});
```

Bad because:

- Async logic in computed
- Side effects

---

### Correct (Watch)

```js
watch(search, async (value) => {
  users.value = await fetchUsers(value);
});
```

---

# Caching Difference

### Computed

```js
const total = computed(() => {
  console.log('computed');
  return price.value * quantity.value;
});
```

Template:

```
{{ total }}
{{ total }}
{{ total }}
```

Console:

```
computed
```

Runs once and caches the result.

---

### Method

```js
function total() {
  console.log('method');
  return price.value * quantity.value;
}
```

Template:

```html
{{ total() }}
{{ total() }}
{{ total() }}
```

Console:

```
method
method
method
```

Runs every render.

# Real-World Watch Examples

### API Call

```js
watch(search, async (value) => {
  products.value =
    await getProducts(value);
});
```

---

### Save to Local Storage

```js
watch(theme, (value) => {
  localStorage.setItem(
    'theme',
    value
  );
});
```

---

### Analytics

```js
watch(selectedPlan, (plan) => {
  analytics.track(plan);
});
```

---

### Route Changes

```js
watch(
  () => route.params.id,
  async (id) => {
    user.value = await getUser(id);
  }
);
```

Very common in Vue applications.

# watchEffect vs watch

### watch

Explicit dependency

```js
watch(search, () => {
  console.log(search.value);
});
```

---

### watchEffect

Automatic dependency tracking

```js
watchEffect(() => {
  console.log(search.value);
});
```

Vue automatically tracks `search`.

# Interview Question

### Can computed replace watch?

No.

Computed:

```js
const total = computed(() =>
  price.value * quantity.value
);
```

Calculates a value.

Watch:

```js
watch(search, fetchUsers);
```

Performs an action.

Different purposes.

# Quick Comparison

|Feature|Computed|Watch|
|---|---|---|
|Returns value|✅|❌|
|Cached|✅|❌|
|Async support|❌|✅|
|API calls|❌|✅|
|Derived state|✅|❌|
|Side effects|❌|✅|
|Local storage updates|❌|✅|
|Analytics|❌|✅|

# Senior-Level Interview Answer

Computed properties are used for deriving values from reactive state and are cached based on their dependencies. Watchers are used for side effects such as API calls, local storage synchronization, analytics tracking, or reacting to route changes. My rule of thumb is: if I need to calculate a value for the UI, I use computed; if I need to perform an action when state changes, I use watch.
