## Button.vue

```vue
<template>
  <button
    :disabled="disabled"
    @click="handleClick"
  >
    {{ label }}
  </button>
</template>

<script setup>
const props = defineProps({
  label: String,
  disabled: Boolean
});

const emit = defineEmits(['click']);

function handleClick(event) {
  emit('click', event);
}
</script>
```

Usage:

```vue
<Button
  label="Save"
  @click="saveUser"
/>
```

# Better Component Design

Instead of:

```vue
<Button label="Save" />
```

Use slots:

```vue
<Button>
  Save
</Button>
```

### Button.vue

```vue
<template>
  <button
    :disabled="disabled"
    @click="handleClick"
  >
    <slot />
  </button>
</template>

<script setup>
const props = defineProps({
  disabled: Boolean
});

const emit = defineEmits(['click']);

function handleClick(event) {
  emit('click', event);
}
</script>
```

Usage:

```vue
<Button>
  Save
</Button>
```

More flexible:

```vue
<Button>
  <span>💾 Save</span>
</Button>
```

# Variants

Interviewers often ask:

"How would you support Primary, Secondary, Danger buttons?"

```vue
<template>
  <button
    :class="buttonClass"
    @click="handleClick"
  >
    <slot />
  </button>
</template>

<script setup>
import { computed } from 'vue';

const props = defineProps({
  variant: {
    type: String,
    default: 'primary'
  }
});

const buttonClass = computed(() => {
  return `btn btn-${props.variant}`;
});
</script>
```

Usage:

```vue
<Button variant="primary">
  Save
</Button>

<Button variant="danger">
  Delete
</Button>
```

# Loading State

Very common in production.

```vue
<template>
  <button
    :disabled="loading"
    @click="handleClick"
  >
    <span v-if="loading">
      Loading...
    </span>

    <span v-else>
      <slot />
    </span>
  </button>
</template>
```

Usage:

```vue
<Button
  :loading="isSaving"
>
  Save
</Button>
```

---

# Prevent Double Click

Senior-level consideration:

```js
async function handleClick() {
  if (props.loading) return;

  emit('click');
}
```

Prevents duplicate API requests.

# Accessibility

Many candidates forget this.

```vue
<button
  type="button"
  :disabled="disabled"
  :aria-disabled="disabled"
>
```

Benefits:

- Keyboard support
- Screen readers
- Better accessibility

---

# Support Native Button Attributes

Forward extra attributes:

```vue
<template>
  <button
    v-bind="$attrs"
    @click="handleClick"
  >
    <slot />
  </button>
</template>
```

Usage:

```vue
<Button
  type="submit"
  data-testid="save-btn"
>
  Save
</Button>
```

# Production-Level Button

Features:

- Variants
- Sizes
- Loading state
- Disabled state
- Slots
- Event emission
- Accessibility
- Attribute forwarding

Example API:

```vue
<Button
  variant="primary"
  size="large"
  :loading="loading"
  :disabled="disabled"
  @click="saveUser"
>
  Save User
</Button>
```

## Interview Answer

If asked:

**"How would you design a reusable button component?"**

Answer:

I would create a component that supports slots for content, variants for styling (primary, secondary, danger), loading and disabled states, proper accessibility attributes, event emission for click handling, and attribute forwarding using `$attrs`. This keeps the component reusable across the application while maintaining a consistent design system.
