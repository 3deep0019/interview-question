"_The Virtual DOM is an in-memory JavaScript representation of the UI tree. When state changes, the framework builds a new virtual tree, **diffs** it against the previous one (reconciliation), and applies the minimal set of real DOM operations. The real DOM is slow to mutate; JS objects are cheap to compare — so this batching wins."_

**React:**

- JSX compiles to `React.createElement(...)` calls, which return **React elements** — plain JS objects describing the tree.
- On state change, React re-invokes the component function to get a new tree, runs its **reconciler** (Fiber, since React 16) to diff old vs new, and commits the delta to the DOM.
- Fiber makes work **interruptible and prioritizable** — high-priority updates (input) can preempt low-priority ones (data list re-render). That's the concurrent rendering foundation.
- Diff heuristics: same type → recurse; different type → replace; lists use `key` to match nodes across renders.

**Vue:**

- Templates compile to a `render` function that produces **VNodes** (Vue's virtual nodes).
- Vue's twist is **fine-grained reactivity** (Proxies in Vue 3). It tracks _which_ reactive properties each component reads. When one changes, only components that depend on it re-render — you rarely need `useMemo` / `React.memo` because the tracking is automatic.
- Vue 3's compiler is smarter than React's runtime — it uses **compile-time hints** (`patchFlags`, static hoisting, block trees) to skip parts of the diff it already knows are static. So the runtime diff cost is lower than React's for equivalent trees.

**One-line comparison** (memorize this):  
_"React re-renders the component subtree and diffs everything; Vue tracks dependencies and only re-renders what actually depends on the changed state, then diffs a smaller tree using compile-time hints. Same idea — Virtual DOM + reconciliation — different trade-offs on where the work happens."_
