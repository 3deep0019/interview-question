# 1. setup()

Runs before the component is created.

### Example: Initialize reactive state

```vue
<script setup>
import { ref } from 'vue';

const count = ref(0);

function increment() {
  count.value++;
}
</script>
```

Use cases:

- Define refs
- Define reactive state
- Computed properties
- Watchers
- Composables

Interview Answer:

setup() is the entry point of the Composition API. Reactive state, computed properties, watchers, and composables are typically initialized here.

---

# 2. onBeforeMount()

Runs before the template is mounted to the DOM.

### Example

```
<script setup>
import { onBeforeMount } from 'vue';

onBeforeMount(() => {
  console.log('DOM not mounted yet');
});
</script>
```

Use cases:

- Rarely used
- Last-minute data preparation

Interview:

 I rarely use onBeforeMount because most logic can be placed in setup() or onMounted().

---

# 3. onMounted() ⭐ Most Important

Runs after the component is inserted into the DOM.

### Example 1: API Call

```vue
<script setup>
import { ref, onMounted } from 'vue';

const users = ref([]);

onMounted(async () => {
  const response = await fetch('/api/users');
  users.value = await response.json();
});
</script>
```

---

### Example 2: Access DOM

```vue
<template>
  <input ref="inputRef" />
</template>

<script setup>
import { ref, onMounted } from 'vue';

const inputRef = ref(null);

onMounted(() => {
  inputRef.value.focus();
});
</script>
```

---

### Example 3: Initialize Chart

```js
onMounted(() => {
  new Chart(canvasElement, config);
});
```

---

### Example 4: Window Event

```js
onMounted(() => {
  window.addEventListener(
    'resize',
    handleResize
  );
});
```

Use cases:

- API calls
- Charts
- Maps
- DOM manipulation
- Third-party libraries

---

# 4. onBeforeUpdate()

Runs before Vue updates the DOM.

### Example

```js
onBeforeUpdate(() => {
  console.log(
    'UI will update soon'
  );
});
```

Use cases:

- Capture old DOM state
- Debugging

Interview:

Rarely used in production.

---

# 5. onUpdated()

Runs after DOM updates.

### Example

```js
onUpdated(() => {
  console.log(
    'DOM has been updated'
  );
});
```

Example:

```vue
<template>
  <div>{{ count }}</div>
</template>
```

```js
count.value++;
```

Triggers:

```
onBeforeUpdate
↓
DOM update
↓
onUpdated
```

Use cases:

- Integrating third-party UI libraries
- Recalculating layout

---

### Dangerous Example

```js
onUpdated(() => {
  count.value++;
});
```

Creates:

```
Update
↓
Updated
↓
Update
↓
Updated
↓
Infinite Loop
```

Common interview trap.

---

# 6. onBeforeUnmount()

Runs before component removal.

### Example

```js
onBeforeUnmount(() => {
  window.removeEventListener(
    'resize',
    handleResize
  );
});
```

Use cases:

- Remove listeners
- Clear timers
- Cancel subscriptions

---

# 7. onUnmounted()

Runs after component removal.

### Example

```js
onUnmounted(() => {
  console.log(
    'Component destroyed'
  );
});
```

Use cases:

- Final cleanup
- Analytics logging

---

# Real Production Example

```vue
<script setup>
import {
  ref,
  onMounted,
  onUnmounted
} from 'vue';

const users = ref([]);

function handleResize() {
  console.log(window.innerWidth);
}

onMounted(async () => {
  const response =
    await fetch('/api/users');

  users.value =
    await response.json();

  window.addEventListener(
    'resize',
    handleResize
  );
});

onUnmounted(() => {
  window.removeEventListener(
    'resize',
    handleResize
  );
});
</script>
```

# Hooks You Actually Use Most

In real-world Vue 3 projects:

```
1. setup()
2. onMounted()
3. watch()
4. computed()
5. onUnmounted()
```

Those account for the majority of day-to-day lifecycle-related work.

# Senior Interview Answer

 In Vue 3, the most commonly used lifecycle hooks are `setup()`, `onMounted()`, and `onUnmounted()`. I use `onMounted()` for API calls, DOM access, charts, maps, and third-party libraries. I use `onUnmounted()` to clean up event listeners, timers, WebSocket connections, and subscriptions to prevent memory leaks. Hooks such as `onBeforeUpdate()` and `onUpdated()` are used less frequently and are generally reserved for advanced DOM synchronization scenarios.
