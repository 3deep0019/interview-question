**Do NOT render 20k DOM nodes.** That's the punchline. Everything else is variations on how.

**Approach 1 — Server-side pagination (default)**

- API returns pages of 20–100.
- UI shows page controls or infinite scroll.
- Simplest, works everywhere, keeps memory bounded.
- Trade-off: user can't do client-side filter/sort across the whole dataset.

**Approach 2 — Windowing / Virtualization (if you _must_ show them all)**

- Only render the ~30 rows currently visible in the viewport. As the user scrolls, recycle DOM nodes.
- Libraries: `vue-virtual-scroller`, `TanStack Virtual` (framework-agnostic), `react-window`, `react-virtualized`.
- 20k rows → 30 DOM nodes → smooth 60fps scroll.

```html
<!-- Vue -->
<RecycleScroller :items="rows" :item-size="40" v-slot="{ item }">
  <div>{{ item.name }}</div>
</RecycleScroller>
```

**Approach 3 — Infinite scroll / cursor-loading**

- Load next chunk when user nears the bottom (`IntersectionObserver` on a sentinel div).
- Combine with virtualization for the best result: infinite scroll + windowing = memory bounded + progressive load.

**Approach 4 — Aggregate, don't enumerate**

- If it's "20k transactions," the user probably doesn't want to _read_ all 20k. They want to search, filter, group, or see a chart. Push the aggregation to the server (SQL `GROUP BY`, Mongo `$group`) and return the summary + top-N results.

**Cross-cutting essentials:**

- **Server-side filter/sort/search** — never do it client-side over 20k rows. Debounce input, send to API, page the result.
- **Skeleton loaders** during fetch so the UI doesn't feel dead.
- **Debounce search input** (~300ms) and **cancel stale requests** with `AbortController`.
- **Cache pages** in memory (or with SWR / TanStack Query / Vue Query) so back-navigation is instant.
- **Column virtualization** too if you have many columns.

**Land it:**  
_"Concretely for a table like this — cursor-paginated API returning 50 at a time, TanStack Virtual for windowing, IntersectionObserver for infinite scroll, filter/sort/search go to the server, and TanStack Query for the caching layer. 20k rows in the DB, ~30 in the DOM at any moment, zero jank."_
